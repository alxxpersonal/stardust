# Codex CLI plugin for Stardust - implementation plan

Build `plugin/codex/`, a Codex-native plugin bundle that wires the Stardust MCP server, injects session-start context, and ships the authoring workflows as Agent Skills, verified end to end against the installed `codex-cli`.

## Header

- **Goal:** a Codex user installs Stardust in two commands and gets the MCP tools, session-start context injection, and the authoring workflows as skills, matching the Claude plugin's value.
- **Architecture:** dedicated `plugin/codex/` bundle (ADR 0049); slash commands transferred directly plus skills (ADR 0050); Claude hook scripts reused, only `policy.txt` neutralized (ADR 0051).
- **Tech stack:** JSON manifests (`.codex-plugin/plugin.json`, `.mcp.json`, marketplace descriptor), `hooks/hooks.json`, POSIX `sh` scripts (copied), `SKILL.md` markdown, and the installed `codex-cli 0.144.1` for verification. Optional Go change in `internal/agentsync`.
- **Global constraints:** ZERO em or en dashes anywhere. No emoji in docs. Conventional commits, no co-author trailers. Self-contained bundle. Follow repo `CLAUDE.md` and `.claude/rules`. Do not pollute the user's real `~/.codex/config.toml`: every install step in verification has a matching cleanup.

## Context

Stardust ships `plugin/claude/`. Codex is a full plugin host (see the research doc). This plan reuses the Claude bundle's assets: `.mcp.json`, `hooks/hooks.json`, `hooks/session-start.sh`, `hooks/prompt-submit.sh`, `hooks/policy.txt`, `scripts/resolve-root.sh`, and `commands/*.md`.
